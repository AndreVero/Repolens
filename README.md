## Overview

**RepoLens Mobile** is an Android application that visualizes structured repository analysis generated by **IBM Bob**.

It transforms complex Android codebases into a clickable, mobile-friendly experience that helps developers understand:

- project architecture
- modules
- features
- dependency injection
- UI structure
- concurrency
- testing gaps
- risks
- recommendations
- action items
- PR readiness

RepoLens was built for the **IBM Bob Hackathon** challenge:

> **Turn idea into impact faster**

The core idea is simple:

```text
Android Repository
        ↓
IBM Bob analyzes the codebase
        ↓
Bob generates structured JSON
        ↓
RepoLens Mobile parses the JSON
        ↓
Developers explore architecture, features, risks, and action items
```

---

## Problem

Large Android projects are difficult to understand quickly.

Before making even a small change, developers often need to answer questions like:

- Where does this feature start?
- Which screen, ViewModel, UseCase, Repository, and API are involved?
- Which modules depend on each other?
- Where is dependency injection configured?
- Which flows use coroutines, StateFlow, background workers, or shared state?
- What parts of the codebase are risky?
- What tests are missing?
- Is this change ready for a pull request?

This is especially painful in:

- large mobile teams
- legacy Android projects
- multi-module repositories
- codebases with mixed architecture patterns
- projects with weak documentation
- fast-moving product teams

RepoLens is designed to reduce that discovery time.

---

## Solution

RepoLens Mobile uses **IBM Bob** as the repository analysis engine.

Bob analyzes an Android project and produces a structured JSON report.  
RepoLens Mobile then visualizes this report using a clean **Material 3** Android interface.

The app is not a generic AI chatbot.  
It is a focused Android-first visualizer for repository intelligence.

---

## Why Android-first?

RepoLens intentionally focuses on **Android projects**.

As an Android developer, I wanted to solve a real problem I understand from inside: Android projects are not just collections of files. A production Android app usually includes:

- Jetpack Compose or XML UI
- ViewModels
- UI state models
- Navigation
- UseCases
- Repositories
- Networking
- Persistence
- Dependency Injection
- Coroutines and Flow
- Background work
- Analytics
- Feature modules
- Unit and UI tests
- PR and QA workflows

RepoLens is designed around these Android-specific concepts instead of being a generic source-code summarizer.

## How It Works

1. Open an Android repository in IBM Bob.
2. Ask Bob to analyze the repository using the RepoLens JSON schema.
3. Bob generates a structured JSON report.
4. Add the report to the Android app assets.
5. Run RepoLens Mobile.
6. Explore architecture, features, risks, recommendations, action items, and PR readiness in a clickable Material 3 UI.

```text
IBM Bob IDE
   └── analyzes repository
          └── generates RepoLens JSON
                 └── RepoLens Mobile loads report
                        └── visualizes repository intelligence
```

## Expected JSON Report

RepoLens expects a structured JSON report with top-level sections like:

```json
{
  "metadata": {},
  "repository": {},
  "metrics": {},
  "architecture": {},
  "modules": [],
  "features": [],
  "dependencyInjection": {},
  "concurrency": {},
  "uiLayer": {},
  "networking": {},
  "persistence": {},
  "testing": {},
  "risks": [],
  "prReadiness": {},
  "documentation": {},
  "bobUsage": {}
}
```

The schema was designed with IBM Bob to represent Android repository structure in a way that can be rendered as mobile UI.

The app uses Kotlinx Serialization models that match the RepoLens JSON schema.

- modules

- dependency injection
- concurrency

- persistence

### Repository Layer

The repository layer loads the JSON report from assets and maps it into strongly typed Kotlin models.

## Limitations

This is a hackathon proof of concept.

Current limitations:

- RepoLens does not perform live repository analysis inside the app.
- Reports must be generated by IBM Bob first.
- The app currently loads a bundled JSON report.
- AI-generated insights should always be reviewed by a human developer.
- The report represents a snapshot of the repository at the time of analysis.
